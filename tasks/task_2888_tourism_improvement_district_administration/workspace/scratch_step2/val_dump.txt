== concurrency_rules
- rule_id: statement-amendment-stale-statement
  parent_entity: AssessmentStatement
  write_endpoint: POST /assessment-statements/{id}/amendments
  occ_field: expected_statement_version
  description: 'Filing an amended statement against an AssessmentStatement whose version
    has

    advanced since the operator last read it is rejected. An amended filing

    legitimately supersedes the prior revision, so the second writer''s request is

    not blocked by any state precondition; the stale expected_statement_version is

    the only thing that distinguishes it. A dispute resolution or a preceding

    amendment silently bumps the statement''s version, so the operator''s cached

    view goes stale without any state change the operator can observe.

    '
  error_id: ERR_STALE_STATEMENT_VERSION
  http_status: 412
- rule_id: work-plan-amendment-stale-plan
  parent_entity: AnnualWorkPlan
  write_endpoint: POST /annual-work-plans/{id}/amendments
  occ_field: expected_work_plan_version
  description: 'Submitting a revised expenditure-line set against an AnnualWorkPlan
    whose

    version has advanced since the administrator last read it is rejected. A

    revision legitimately supersedes the prior expenditure_lines, so nothing in

    the plan''s state machine blocks a second revision; the stale

    expected_work_plan_version is the only discriminator. The AMENDMENT_PENDING

    auto-transition driven by a funding_ratio recompute bumps the plan''s version

    between the read and the write.

    '
  error_id: ERR_STALE_WORK_PLAN_VERSION
  http_status: 412
