# PRD Bench Unit Test Generator

Generate a **complete, rigorous Python unit test suite** that validates whether an API implementation faithfully satisfies every requirement in a given PRD.

## Input

A single **working directory** containing:
- **`SCAFFOLD.yaml`** — the scaffold: `entities:`, `state_machines:`, `calculations:`, `validations:`, `endpoints:`, `errors:`, `roles:`
- **`SCAFFOLD_DIFFICULTY_DESIGN.yaml`** — the depth Test Targeting Index (single top-level key `scaffold_difficulty_design:`) — 9 difficulty rules × ≥2 hand-curated instances each
- **`SCAFFOLD_CORNER_DESIGN.yaml`** — the breadth Coverage Index (single top-level key `scaffold_corner_design:`) — exhaustive enumeration of every testable claim derivable from `SCAFFOLD.yaml`'s declared surface, each pre-audited for `setup_api_calls` reachability and literal-asserted expected values
- **`*.md`** — the PRD document generated from the scaffold

The skill reads all four files from this directory, then creates `test_helpers/` and `test_suite/`
as subdirectories under it. All generated code uses **relative imports** within this directory.

**Source priority**: the scaffold and the two design indices (`scaffold_difficulty_design`, `scaffold_corner_design`) are the **structural enumeration**; the PRD is the **contract**. Both indices feed identically into Stage 2 §2.1 as two queues — difficulty first (depth), corner second (breadth) — and BOTH go through the same PRD-first Core rule (see "Testing Philosophy" below). This skill does NOT walk `SCAFFOLD.yaml` to extract claims; the two design indices together ARE the structural walk, and `scaffold_corner_design` instances are already pre-tagged with the claim taxonomy so downstream consumers do not need to re-derive it.

**Coverage targets** (both queues mandatory, see §2.1):
- `scaffold_difficulty_design` — every instance covered by ≥2 tests, subject to the Core rule.
- `scaffold_corner_design` — every non-stub instance covered by ≥1 test, subject to the Core rule; `excluded_because:` stubs are NOT translated (the cited difficulty-design instance owns the assertion).

```
{working_dir}/                          # ← input directory (provided by user)
├── SCAFFOLD.yaml                       #    input: scaffold tables
├── SCAFFOLD_DIFFICULTY_DESIGN.yaml     #    input: difficulty-design index
├── SCAFFOLD_CORNER_DESIGN.yaml         #    input: corner-design index
├── PRD.md                              #    input: PRD
├── test_helpers/                       #    output: generated by Stage 1
│   └── ...
└── test_suite/                         #    output: generated by Stage 2
    └── ...
```

See `references/example-test-patterns.md` for concrete Python code patterns.

## Responsibility Boundary

This skill generates **test code only**. It does not handle server lifecycle, test execution, or result collection — those are the `prd-bench-local-runner` framework's job.

| Concern | Owner | Details |
|---|---|---|
| Server start/stop | `prd-bench-local-runner` | Spawn subprocess, poll readiness, SIGTERM on exit |
| Crash recovery | `prd-bench-local-runner` | Per-test liveness check via pytest plugin |
| `API_BASE_URL` injection | `prd-bench-local-runner` | Set as env var before pytest subprocess |
| `PYTHONPATH` setup | `prd-bench-local-runner` | Ensures `test_helpers` and framework are importable |
| Test execution | `prd-bench-local-runner` | Invokes `pytest` with JUnit XML output |
| Result collection | `prd-bench-local-runner` | Parses JUnit XML → structured JSON |
| **test_helpers/** | **this skill** | PRD-specific: types, api client, factories, assertions, fixtures |
| **test_suite/** | **this skill** | Claim-driven test files |

**The generated tests assume the server is already running and reachable at `API_BASE_URL`.** They never start, stop, or health-check the server — that's the runner's guarantee.

### Framework API Quick Reference

**CRITICAL: Use these exact signatures. Do NOT guess parameters.**

```python
# --- Validators (from prd_bench_local_runner.testing) ---

validate_success(response, expected_status=200) -> dict
# Returns the data payload. Asserts status code and envelope structure.

validate_error(response, expected_error_id, expected_status=None) -> dict
# Returns error_data dict. If set_error_http_status_map() was called, HTTP status
# is auto-checked from the map (no need to pass expected_status explicitly).

validate_error_is_one_of(response, acceptable_error_ids: list) -> str
# For race condition tests where multiple error outcomes are valid.
# Returns the actual error_id string. Does NOT check HTTP status.

validate_paginated(response) -> tuple[list, dict]
# Returns (data_list, meta_dict). Takes ONLY the response — no status code argument.
# meta_dict contains: total_count, has_more, limit, offset.
# Usage: data, meta = validate_paginated(resp)

get_success_data(response) -> dict
# Lenient validator — accepts any 2xx status. Use in fixtures.py for setup calls.

# --- Error registration (NOT exported from top-level package) ---

from prd_bench_local_runner.testing.validators import set_error_http_status_map
set_error_http_status_map(mapping: dict) -> None
# Registers error_id → HTTP status mapping. Call once at import time in api_errors.py.

# --- Race condition utilities (from prd_bench_local_runner.testing) ---

run_race(*operations) -> list[Response]
# Takes VARARGS of zero-arg callables (NOT a list). Each callable returns Response.
# Usage: results = run_race(lambda: api.foo(...), lambda: api.bar(...))
# Returns list of Response objects in completion order (not submission order).

assert_race_outcome(results: list, expected_successes: int, expected_failures: int) -> dict
# Counts 2xx as successes, 4xx+ as failures. Returns {"successes": [...], "failures": [...]}.

assert_exactly_one_succeeds(result_a, result_b) -> dict
# Shortcut for assert_race_outcome([result_a, result_b], 1, 1).

assert_at_least_one_succeeds(*results) -> dict
# Asserts at least one result is 2xx.
```

## Testing Philosophy

The test suite answers: "Does the implementation correctly handle requirement X?" for every X in the PRD. The organizing principle is **testable claims**, not code structure.

### Core rule — PRD coverage AND unique derivability

A test is legitimate only when BOTH are true:

1. **Coverage** — a verbatim PRD sentence names the specific rule the test asserts (the `error_id`, threshold, state transition, side effect, or field presence/type). The implementer sees only the PRD; "the scaffold says so" is not coverage.
2. **Unique derivability** — two PRD-only readers would arrive at the same observable outcome; neither could plausibly ship a different-but-still-PRD-consistent variant on which the test would fail.

If either fails → **skip the test** and log the gap under the appropriate Silence-pattern category below. Do not weaken the assertion, downgrade to a generic HTTP-status check, or emit `pytest.mark.skip` / `skipif` / `xfail`.

If both pass → **the test MUST be generated and MUST execute**. Setup size is never an excuse — build the fixture (the entire `SCAFFOLD_DIFFICULTY_DESIGN.yaml` index exists to motivate hard fixtures, including cross-entity cascade terminal states like `Tenant.TERMINATED` reached via `Bill.PAID`). "Fixture would be complex" is a work item, not a justification.

**The two-reader thought experiment** — operate this before emitting any test:

> Construct two hypothetical implementers, each reading only PRD.md (never scaffold). For the behavior this test asserts, both must arrive at the **same observable outcome**. If one could reasonably implement variant A and the other variant B — both faithful to PRD prose — then PRD has left a design space open. Any test that hard-codes A or B over the other must **not** be generated.

### Mandatory PRD citation (C1 / C2 / C3) + Scaffold citation (C4)

Every test's docstring must carry a PRD citation proving the asserted rule appears in the contract the implementer actually sees, AND a scaffold citation naming the design-index instance that drove generation. Any failure invalidates the test:

- **C1 Verbatim, not paraphrased.** The quoted text must survive a literal `grep` of PRD.md (modulo surrounding whitespace).
- **C2 Rule-bearing, not endpoint-titular.** The sentence expresses the specific rule — the `error_id`, threshold, transition, side effect, field presence/type. Quoting the endpoint title (`POST /adopters/{id}/home-visits`) or section heading is **not sufficient** — those strings may appear without encoding the behavior.
- **C3 Non-abbreviated.** Quote the full sentence carrying the rule. A fragment like *"A pass sets…"* hides whether the rule actually covers the specific field/transition under assertion.
- **C4 Scaffold citation, exactly one line.** End the docstring with `Design: Difficulty/<rule_id>/<instance.name>` (queue A) or `Design: Corner/<section>/<instance.name>` (queue B), copied verbatim from the source yaml's `name:`. No third namespace; no untagged tests.

Citation format:

```python
def test_void_invoice_with_partial_payment_rejected(api):
    """PRD §3.6: "an invoice that has received any money cannot be voided
    until the money is refunded, and such an attempt is rejected with
    ERR_INVOICE_HAS_PAYMENTS."

    Design: Difficulty/cross_entity_state_dependency/invoice_void_blocked_by_payment_presence
    """
```

For rules spanning multiple sentences, quote each in full rather than fusing them:

```python
def test_approve_requires_animal_current_version(api):
    """PRD §2.7: "stale-version checks are the last precondition; on mismatch
    the platform returns ERR_STALE_ANIMAL_DATA."
    PRD §3.3: "Approval re-evaluates animal_version_pinned against the live
    Animal.version at the moment of the call."

    Design: Corner/validations/approve_stale_animal_version_rejected
    """
```

### Silence patterns — skip unless PRD explicitly states the rule

Before generating a test derived from any of these scaffold features, search PRD for the specific rule. If PRD does not state it, MUST **skip** the instance.

| Skip category | Scaffold source | When PRD is silent |
|---|---|---|
| `validation-priority` | `validations[].priority` | Do NOT test "error A fires before error B". Test each validation in an isolated scenario where only one can fail. |
| `concurrency-occ` | `concurrency_rules[]` (each entry is an OCC rule with `write_endpoint`, `occ_field`, `error_id`) | Generate as an OCC stale-version test asserting the rule's exact `error_id` (sequential or `run_race` form — OCC's version check at commit time makes either deterministic). If PRD does not state both the `expected_<parent>_version` requirement and the rejection `error_id`, SKIP. |
| `cross-entity-cascade` | `endpoints[].side_effects` spanning entities | Test primary effect only. Omit secondary (e.g., the `animal.version` bump from hold creation). |
| `applies_to-scope` | `validations[].applies_to` endpoint list | Generate tests only for endpoints PRD prose explicitly covers — not the scaffold's broader list. |
| `computed-field` | Scaffold declares computed field; PRD mentions it only inside a formula | Do NOT assert field presence/value on response (a reader could correctly omit it from the serializer). |
| `default-value` | Optional input field; PRD says "optional" without naming the server-side default | Do NOT assert a specific default (`null` / `false` / omission all faithful). |
| `branch-asymmetry` | Scaffold renders PASS + FAIL branches with equal side_effects; PRD compresses one branch | Do NOT assert the compressed branch's dropped effects. |
| `enum-write-pathway` | Scaffold enum value in allowed-list; PRD never states what writes it | Do NOT assert a specific branch writes a specific enum value. |
| `error-precedence` | PRD names "loser gets `ERR_A`" but does not commit to pre-empting the state-check path | Use `validate_error_is_one_of([ERR_A, ERR_INVALID_STATE])`. |

Gaps surfaced this way are PRD bugs, not test bugs to paper over.

### Other testing principles

- **Boundary precision** — for every numeric threshold, test X-1, X, X+1.
- **Data isolation** — every test creates its own entities; no shared mutable state. **The test harness kills the API server process and re-launches it via `start.sh` before every individual pytest test.** Each test therefore starts against an empty database — no entities, no state, nothing carried over from a previous test. Every fixture, factory, and setup helper MUST build its preconditions from scratch using only PRD-declared endpoints.
- **Domain language** — file / class / function names use PRD terminology, not scaffold table references.

## Stage 1: Generate `test_helpers/`

This stage generates **only PRD-specific code** — types, endpoint methods, entity assertions,
factories, domain constants, fixtures. All generic utilities come from `prd_bench_local_runner.testing`.

### 1.1 `types.py` — Data Structures

Derived from `SCAFFOLD.yaml`'s `entities:` and `state_machines:`. Generate status enums, entity TypedDicts, role enums. No generic envelope types (those are in the framework).

**`common_fields` branching (mandatory):** Entities with `common_fields: true` carry `id`, `created_at`, `updated_at`, and `version`. Entities with `common_fields: false` (append-only logs, pairings, ledger entries, config snapshots) carry **only** `id` and `created_at` — their TypedDicts MUST omit `updated_at` and `version`. A TypedDict that lists `updated_at`/`version` on an append-only entity forces downstream assertions to demand fields the implementer is correctly told not to return.

```python
"""Domain types: entity TypedDicts, status enums, role enum."""
from enum import Enum
from typing import TypedDict, Optional, List

class {Entity}Status(str, Enum):
    STATE_A = "STATE_A"
    STATE_B = "STATE_B"

class UserRole(str, Enum):
    ROLE_A = "RoleA"
    ROLE_B = "RoleB"

# common_fields: true — carries id + created_at + updated_at + version
class {Entity}(TypedDict):
    id: str
    status: str
    field_a: str
    computed_field: float
    created_at: str
    updated_at: str
    version: int

# common_fields: false — append-only, carries ONLY id + created_at
class {AppendOnlyEntity}(TypedDict):
    id: str
    created_at: str
    # ... entity-specific fields, but NO updated_at, NO version
```

### 1.2 `api_client.py` — PRD-Specific Endpoint Methods

**Subclass** `GenericApiClient` from the framework. Only generate the endpoint methods (one per row in `SCAFFOLD.yaml`'s `endpoints:`). The base `_request()` method is inherited.

```python
"""API client: one method per endpoint defined in the PRD."""
from prd_bench_local_runner.testing import GenericApiClient

class ApiClient(GenericApiClient):
    # Generate one method per endpoint:
    def create_{entity}(self, payload, headers):
        return self._request("POST", "/{entities}", payload, headers)
    def get_{entity}(self, entity_id, headers):
        return self._request("GET", f"/{entities}/{entity_id}", headers=headers)
    def list_{entities}(self, headers, params=None):
        return self._request("GET", "/{entities}", headers=headers, params=params)
    def activate_{entity}(self, entity_id, headers):
        return self._request("POST", f"/{entities}/{entity_id}/activate", headers=headers)
    # ... etc

api_client = ApiClient()
```

### 1.3 `api_errors.py` — Error Catalog + Framework Registration

Derived from `SCAFFOLD.yaml`'s `errors:`. After defining the mapping, **register it with the framework** so `validate_error()` can cross-check HTTP status codes automatically.

```python
"""Error IDs and HTTP status mapping (PRD §5)."""
from enum import Enum

    ERR_{ENTITY}_NOT_FOUND = "ERR_{ENTITY}_NOT_FOUND"

HTTP_STATUS_CODES: dict[str, int] = {
    ApiErrorId.ERR_INVALID_REQUEST: 400,
    ApiErrorId.ERR_{ENTITY}_NOT_FOUND: 404,

}
```

### 1.4 `assertions.py` — PRD-Specific Entity Assertions

Generate `assert_{entity}(data)` for each entity using the framework's generic validators
(`is_valid_uuid`, `is_iso8601_timestamp`) internally. Also generate domain-specific invariant
checkers (e.g., `assert_plan_invariants`) using `assert_cost_precision` from the framework.

```python
"""Entity assertions and domain invariant checkers."""
import pytest
from prd_bench_local_runner.testing import (
    is_valid_uuid, is_iso8601_timestamp, assert_cost_precision,
)

def assert_{entity}(data: dict):
    assert is_valid_uuid(data.get("id", "")), "id must be valid UUID"
    assert is_iso8601_timestamp(data.get("created_at", "")), "created_at must be ISO 8601"
    assert isinstance(data["field_a"], str) and len(data["field_a"]) > 0
    assert data["status"] in ["STATE_A", "STATE_B", "STATE_C"]
    # ... all fields from the entity definition

def assert_{parent}_invariants(data: dict):
    """Domain invariants that must hold after any operation."""
    assert data["cost_balance"] >= 0
    assert data["cost_balance"] <= data["total_budget"]
    assert_cost_precision(data["cost_balance"])
    assert data["safety_score"] >= 0
```

### 1.7 `test_users.py` — Pre-Built Role Headers

Uses `build_user_headers()` from the framework. Driven by `roles[].identity` in `SCAFFOLD.yaml`. **This file emits two things per role:**

- **A shared-constant entry in `TEST_USERS`** — used only by tests whose success does NOT depend on the caller owning the subject resource (e.g., 400-on-bad-payload, 404-on-missing-resource, or calls by `opaque` roles).
- **A per-instance builder function `make_<role>_headers(user_id)`** — **mandatory for every role whose `identity` is `entity_backed:<EntityName>`**. Fixtures MUST call this builder with the actual entity's `id` when the downstream call is ownership-gated (e.g., `make_restaurant_headers(restaurant["id"])` after `create_restaurant`). Falling back to the shared constant for entity_backed roles reproduces the canonical bug: `X-User-ID` is a string that never equals any real entity's `id`, so every ownership check rejects every request, cascading "Setup failed" into dozens of tests.

```python
"""Pre-built role headers for every role in the PRD."""
from prd_bench_local_runner.testing import build_user_headers

# Shared constants — safe for opaque roles, and for tests that don't exercise ownership.
TEST_USERS = {
    # entity_backed role: shared constant is a fallback for non-ownership tests only.
    "role_a_headers": build_user_headers("test-role-a-1", "RoleA"),
    # opaque role: shared constant is the canonical form.
    "role_admin_headers": build_user_headers("test-admin-1", "Admin"),
}


# Per-instance builders — required for every entity_backed role.
def make_role_a_headers(user_id: str) -> dict:
    """For RoleA (entity_backed:EntityA). Pass the actual EntityA.id as user_id
    whenever the call is ownership-gated."""
    return build_user_headers(user_id, "RoleA")
```

### 1.8 `fixtures.py` — Composite Setup Helpers

This is the **most important and most substantial** file in `test_helpers/`. It encapsulates multi-step setup sequences so tests can focus on assertions, not plumbing. It is normal and expected for this file to be large (500–1000+ lines for complex PRDs).

The reason fixtures matter so much: **most interesting test claims require the system to be in a specific state that takes 5–15 API calls to reach.** A test for "bio-risk threshold at 6000 minutes" cannot just create one entity — it must create a plan, activate it, create a rotation, create a resource with known cost, create a procedure spanning 5980 minutes, create an assignment, approve it, schedule it, and THEN create the 100-minute procedure under test. Without fixtures, every test would repeat this 9-step preamble.

#### How to identify which fixtures to generate

Walk through each test claim from Phase 2.1. For each claim, ask: "What state must the system be in before I can test this?" Count the API calls needed to reach that state. If ≥3 claims share the same multi-step preamble, extract it into a fixture.

#### Fixture tiers (generate all tiers that apply to this scaffold)

#### Key design principle for fixtures

Every fixture should accept `**overrides` for the values that tests need to control. A threshold test needs to control `minutes_used` and `cost_per_minute`. A budget test needs to control `budget`. A certification test needs to control which certs exist. The fixture provides sensible defaults for everything else.

Fixtures use `get_success_data()` (lenient validator) internally, not `validate_success()`, so setup failures produce clear "Setup failed" errors instead of confusing assertion failures.

**Identity threading (mandatory):** after a fixture creates an `entity_backed:<EntityName>` entity, any ownership-gated call in the same fixture (or in a consumer fixture) MUST use `make_<role>_headers(entity["id"])` — never fall back to `TEST_USERS["<role>_headers"]`. See §1.7 above (`test_users.py`) for the rule and the canonical-bug explanation.

### 1.9 `__init__.py` — Barrel Export

Re-export both framework utilities and PRD-specific code. Tests use one import source.

```python
"""Barrel export: framework generics + PRD-specific code."""
# Framework generics (re-exported for convenience)
```

## Stage 2: Generate `test_suite/` (AFTER Stage 1 is complete)

**Stage 2 MUST NOT begin until Stage 1 is fully written to disk.** Before writing any test file, read back the generated `test_helpers/` code to know the exact:
- `ApiClient` method names and signatures (from `api_client.py`)
- Fixture function signatures and return types (from `fixtures.py`)
- Exported names (from `__init__.py`)
- Error ID constants (from `api_errors.py`)
- Factory function names and parameters (from `factories.py`)
- Assertion function signatures (from `assertions.py`)

This eliminates the most common generation bug: test_suite guessing test_helpers' interface instead of reading it. Tests import everything from `test_helpers` and focus purely on test logic.

### 2.1 Translate Design Indices to Tests

§2.1 consumes two upstream design indices and translates each into pytest tests under the same procedure:

| Queue | File | Coverage target | Docstring tag |
|---|---|---|---|
| **(A) Difficulty** | `SCAFFOLD_DIFFICULTY_DESIGN.yaml` | ≥2 tests per instance | docstring line `Design: Difficulty/<rule_id>/<instance.name>` |
| **(B) Corner** | `SCAFFOLD_CORNER_DESIGN.yaml` | ≥1 test per non-stub instance | docstring line `Design: Corner/<section>/<instance.name>` |

**Run (A) before (B).** Difficulty setups are more complex and produce composite fixtures in `test_helpers/fixtures.py` that corner translations reuse.

**PRD-first is the value system.** A `test_recipe` is structural enumeration — the scaffold's claim that something *could* be tested. PRD is the contract. **Only rules PRD verbatim-covers AND uniquely-derives become tests.** Everything else is skipped — never weakened, never marked skip/xfail.

**Per-instance procedure** (applies identically to BOTH queues' non-stub instances):

1. **Read `grounds:`** — locates the rule the instance asserts in `SCAFFOLD.yaml`.
2. **Locate the PRD prose** — find the verbatim sentence stating that rule. This is what the generated test's docstring cites (see Testing Philosophy § Mandatory PRD citation).
3. **Apply the PRD-first two-condition filter** (Testing Philosophy § Core rule):
   - **Coverage** — does a verbatim PRD sentence name the rule?
   - **Unique derivability** — does it pin the outcome to a single answer every PRD-only implementer would arrive at?

   If either fails, skip the instance.
4. **Translate `test_recipe.setup_api_calls`** — each structured call becomes an `ApiClient` method call in the fixture; `${var}` resolves against earlier `captures:`. The `setup_api_calls` chain is the canonical source for *how* to set up; the natural-language `setup:` lines are human-readable annotations for fixture naming and docstrings. Reuse helpers from `test_helpers/fixtures.py` when chain prefixes are shared across instances.
5. **Translate `test_recipe.trigger`** — same structured form.
6. **Translate each `test_recipe.assert`** — pin to PRD-exact field names. Literal expected values are already pre-computed in the YAML; copy verbatim, do not recompute.
7. **Tag the docstring** with the queue's docstring tag (see table) so the Completeness audit can map every test back to its upstream instance.

**`excluded_because:` stubs (queue B only) are NOT translated** — they have no `test_recipe`; the cited difficulty-design instance under queue (A) owns the assertion. Verify the `difficulty_instance` cross-reference resolves to a `name:` in `SCAFFOLD_DIFFICULTY_DESIGN.yaml`; a broken pointer is a corner-design bug — skip the stub, do not emit a placeholder test.

**No freelance test discovery.** The two design indices together ARE the structural walk; this skill does not walk `SCAFFOLD.yaml` to invent additional tests. If a guide-applicable claim is missing from either design index, ignore the gap — do not invent a test. This skill's value is faithful translation + PRD adjudication.

**What Stage 1 must anticipate:** pre-scan both yamls for `test_recipe.setup_api_calls` chains needing non-trivial composite state (anything beyond a single POST) and pre-build the corresponding composite fixtures in `test_helpers/fixtures.py` (e.g., `setup_restaurant_near_tier_boundary`, `setup_rider_with_bonus_tier`). Stage 2 imports these by name; no inline chain re-invention.

### 2.2 Organize Claims into Test Files

Cluster claims into coherent test files:

1. **Group by testing concern, not scaffold table.** A state transition claim and its side-effect-on-ledger claim belong together in a "workflows" file.

2. **One file per concern with ≥5 tests.** Smaller concerns fold into the nearest related file.

3. **Name files in domain language.** Prefer `test_booking_conflicts.py` over `test_constraints.py`.

4. **Number for reading order** (`test_01_`, `test_02_`, ...) from simple to complex.

A Starter PRD might produce 3–4 test files. An Expert PRD might produce 10–15.

### 2.3 Generate Test Files

For each file, generate all test functions. Every test function must:
- Have a descriptive name using domain language: `test_{what}_{scenario}`
- Include a PRD citation in its docstring (see Testing Philosophy § Mandatory PRD citation)
- Create its own entities via `test_helpers` factories and fixtures
- Assert the direct result AND every side effect via `test_helpers` assertion helpers

**Patterns to apply:**
- `@pytest.mark.parametrize` for families (invalid transitions, SQL payloads, missing fields, unauthorized roles)
- `pytest.approx(expected, abs=0.01)` for decimal precision
- `concurrent.futures.ThreadPoolExecutor` for concurrency tests
- `class TestXxx:` for grouping related tests within a file

See `references/example-test-patterns.md` §2.1–2.10 for concrete test patterns covering CRUD, state machines, constraints, calculations, cascades, finalization, edge cases, security, concurrency, and end-to-end integration.

## Generation Quality Rules

These rules apply regardless of generation approach. They address code quality issues that
cannot be caught by reading test_helpers code — they require understanding of the PRD itself.

### Field names are PRD-exact — never abbreviated

```python
# WRONG — abbreviated or guessed
product["price"]              # PRD says "base_price"
promo.get("value")            # PRD says "promo_value"
settlement["commission_amount"]  # PRD says "total_commission"

# RIGHT — exact PRD field names in both test_helpers AND test_suite
product["base_price"]
promo.get("promo_value")
settlement["total_commission"]
```

This applies to both layers: test_helpers (factories, assertions, api_client) and test_suite.

### Required vs optional fields follow the PRD

Before parametrizing `test_missing_required_field`, check each field in the PRD:
- `required: false` or has a `default` → optional, do NOT test as required
- All other `source: input` fields → required, test omission

## Code Style

- **pytest** (not `unittest.TestCase`). Module-level functions or `class TestXxx:` groupings.
- `pytest.fixture` for setup. Session-scoped for API client, function-scoped for data.
- Descriptive assertion messages: `assert x == y, f"Expected {y}, got {x} after {action}"`
- No mocking — tests hit the real API. These are integration-level PRD compliance tests.
- Each test is independent. No ordering dependencies.
- All imports from `test_helpers`, not inline infrastructure in test files.
- **Comments and docstrings in generated `test_helpers/` and `test_suite/` code must never mention "scaffold" or scaffold section/table references (e.g., "Table 1", "Table 6", "§1.1", "§1.6"); reference only the PRD.** Example templates may include scaffold labels for the skill author's convenience — strip them when emitting real code.

## Completeness

### Coverage audit

The two design indices are the **only** source of tests. Walking `SCAFFOLD.yaml` directly to invent baseline / smoke / endpoint-coverage tests is forbidden (see §2.1 "No freelance test discovery"). Tick:

- [ ] Every `scaffold_difficulty_design[*].instances[*]` has at least TWO tests tagged docstring line `Design: Difficulty/<rule_id>/<instance.name>` (see §2.1 queue A). Any shortfall is a Stage 2 failure.
- [ ] Every non-stub `scaffold_corner_design[*].instances[*]` has at least ONE test tagged docstring line `Design: Corner/<section>/<instance.name>` (see §2.1 queue B). Any shortfall is a Stage 2 failure. `excluded_because:` stubs are NOT translated (the cited difficulty-design instance under queue A owns the assertion) — verify the cross-reference resolves, but do not emit a test.

### Final PRD-citation pass (mandatory)

Sweep every test function after generation and tick each item:

- [ ] **Docstring carries a PRD citation** meeting C1/C2/C3 (see Testing Philosophy).
- [ ] **Verbatim check** — a distinctive ≥8-word substring of the citation survives a literal `grep` of PRD.md. If not, either rewrite to match PRD or remove the test (never rewrite PRD from test code).
- [ ] **Rule-bearing, not endpoint-titular** — citations that are just HTTP method + path or section heading are red flags. Confirm the asserted rule is stated elsewhere in PRD prose; otherwise delete the test.
- [ ] **Asserted `error_id` is named in PRD prose** (not just the §5 table). If PRD describes no trigger condition for `ERR_FOO`, remove the test.
- [ ] **Asserted priority/ordering is named in PRD prose.** Tests of the form "when A and B both fail, A is reported" require explicit PRD precedence; otherwise split into two single-failure tests or remove.
- [ ] **Two-reader test** — for each test, re-ask whether a faithful PRD-only implementer could ship an implementation that fails this test. If yes, remove or relax (e.g., `validate_error_is_one_of([...])`, drop optional-field presence assertion).
- [ ] **No `pytest.mark.skip` / `skipif` / `xfail` remains** — any surviving skip must cite a Silence-pattern category from Testing Philosophy. "Setup complexity" / "folded into another test" is never a legitimate reason.

This pass is the last line of defense against scaffold-leakage; a suite that passes it is guaranteed implementable from PRD alone, with every assertion traceable to a verbatim PRD sentence that uniquely determines the expected behavior.

### Final Scaffold-citation pass (mandatory)

Sweep every test function after generation and tick:

- [ ] **Docstring ends with exactly one `Design: Difficulty/<rule_id>/<instance.name>` or `Design: Corner/<section>/<instance.name>` line (C4)**, copied verbatim from `name:` in the cited yaml and resolving to a real instance.
